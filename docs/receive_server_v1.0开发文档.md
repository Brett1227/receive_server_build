# receive_server 扫码直连文件传输系统 v1.0 开发文档

> 文档目的：完整记录本系统的需求来源、演进过程与当前功能，便于日后复现需求、继续迭代。
> 整理日期：2026-08-05

---

## 一、项目概述

### 1.1 背景
- 某公司有一台**不能联网**的 Windows 电脑（隔离环境），连接了一台特殊打印机，大量材料需要通过这台打印机打印。
- 因电脑不能联网，文件无法通过网络传输过去，传输材料非常不便。

### 1.2 目标
- 在**不联网**（只允许设备间 WiFi 直连）的前提下，前来打印的同事用手机**扫描电脑屏幕上显示的二维码**，即可把文件传输到打印机主机，文件到达主机后自行打印，全程不经互联网。

### 1.3 核心方案
```
手机(有微信/文件) ──扫码──> 电脑屏幕上的二维码 ──> 手机连上电脑 WiFi 热点
        └──(局域网直连 HTTP)──> 文件上传到主机保存目录 ──> 同事自行打印
```
- 关键设计：**二维码只传递"连接凭证"（上传地址）**，不承载文件内容（二维码容量仅 2~3KB，装不下文件）。
- 传输走手机与主机之间的 WiFi 热点局域网直连，不经过互联网。

### 1.4 交付物（拷到主机即可用）
| 文件 | 说明 |
|---|---|
| receive_server.exe | 接收程序（单文件 exe，免安装 Python，含图形窗口） |
| 使用说明.txt | 操作教程 |
| （运行时自动生成）received/ 上传记录.xlsx config.json | 收到的文件 / 上传记录表 / 保存目录配置 |

## 二、需求演进记录（按提出顺序，共 12 轮）

### R1 初始需求：扫码传文件到不联网主机
**需求描述**
1. 有一台不能联网的电脑连接特殊打印机，材料需要通过它打印，但文件传不过去。
2. 设计一个平台：不联网前提下，扫电脑上的二维码即可传文件到主机。
3. 约束确认：允许开 WiFi 热点直连；主机为 Windows；越简单越好；只做单纯文件传输（不需要自动打印）。
4. 支持**自定义保存目录**，且每次传输后保存在**上次设置的自定义目录**（记住目录）。

**实现**
- Python 纯标准库编写 HTTP 上传服务（当时主机不能联网、装不了第三方库）。
- 手机连主机热点后走局域网直连上传。
- 保存目录写入 config.json 持久化记忆；支持 `receive_server.exe "D:\目录"` 指定。
- 同名文件自动加 `(1)` 后缀不覆盖；单文件上限 500MB。

### R2 打包成 exe（主机未装 Python）
**需求描述**：直连打印机的那台电脑没有安装 Python，需要打包成可执行文件。

**实现**
- 用 PyInstaller `--onefile --console` 打包为单文件 exe。
- **关键修复**：PyInstaller 打包后 `__file__` 指向临时解压目录，会导致配置/文件写丢。用 `sys.frozen` 判断，`BASE_DIR` 改为 exe 所在目录。

### R3 屏幕二维码版（重要需求澄清）
**需求描述**：之前理解错了——正确用法是**前来打印的同事扫描"电脑屏幕上显示的二维码"**传文件；步骤是从手机到电脑，文件到电脑后就不用管了（同事自己打印）。之前的二维码是 PNG 图片文件，找不到、不直观。

**实现**
- 程序启动后弹出 tkinter 图形窗口，大屏显示二维码 + 上传地址 + 保存目录 + 接收记录。
- 二维码**程序内动态生成**（优先匹配热点网段 192.168.137.x），IP 变化也不怕。
- 删除单独的二维码 PNG 图片。

### R4 无黑窗口 + 窗口内修改保存目录
**需求描述**
1. 启动后要**关掉命令行黑窗口**（同事不懂电脑，看到命令行会以为故障），只保留 exe 的图形窗口。
2. exe 窗口内要加**"修改保存位置"按钮**，而不是进 PowerShell 改目录。

**实现**
- 打包改用 `--windowed`（无控制台模式），日志改写到 error.log、报错改用弹窗提示（端口占用等）。
- **适配坑**：windowed 模式下 stdout/stderr 为 None，print 会崩溃，需重定向。
- 窗口"保存目录"旁加【修改…】按钮，用文件夹选择对话框改目录，改后立即生效并写入 config.json。

### R5 微信文件导出引导（第一批）
**需求描述**：同事的文件多通过微信接收，而微信文件是封闭管理的，手机文件管理器/网页上传选择器里找不到，系统可能因此没用。要解决"微信文件怎么传到电脑"的问题。

**实现**
- 分析：网页无法直接访问微信私有目录（手机系统安全限制，无技术绕过），唯一路径是**先导出到手机公共存储再上传**。
- 上传页新增可折叠的"微信文件导出"引导（蓝色提示条）。
- 顺带支持**批量上传**（multiple + 逐个上传进度）。

### R6 微信"保存"实测版 + 列表超链接 + 自动开文件夹
**需求描述**
1. 用户实测：现在常用的 Word、PDF 在微信里点开后，右上角三个点弹出页面**直接有"保存"选项**，保存后上传时就能发现文件。据此优化引导步骤。
2. 优化【修改】按钮的点击动效。
3. 简化接收记录：删掉"服务启动"等多余信息，**只留文件列表**，并做成超链接，**点击文件名即可打开文件**。
4. 上传完成后**自动打开保存文件的文件夹**。

**实现**
- 引导简化为：微信点开文件 → 右上角 `···` → **保存** → 回本页选"最近/下载"。
- 按钮增加悬停/按下动效（hover 变色、active 变深、手型光标）。
- 接收记录改为"已接收文件"列表，仅显示 时间+文件名；每行 Text tag 超链接，点击 `os.startfile` 打开文件。
- 收到文件后自动 `os.startfile` 打开保存目录，带 **5 秒节流**（批量上传只弹一次）。

### R7 iPhone 微信保存引导修正
**需求描述**：iPhone 保存微信文件与 Android 不同，正确步骤为：打开文件 → 右上角 `···` → **用其他应用打开** → **存储到"文件"** → 选择位置存储；**若当前位置是 iCloud 云盘，需点"浏览"→ 位置里选"我的 iPhone"** 才能保存到本地。要求将 iPhone 与 Android 分列表述。

**实现**
- 上传页引导改为三块：**Android 文档**（···→保存）、**iPhone 文档**（用其他应用打开→存储到文件→iCloud 提示）、**图片通用**（长按保存相册）。

### R8 热点密码显示 + 必填部门姓名 + 上传记录表
**需求描述**
1. 主页面加一行：**WiFi 热点密码：73556088**（用户指定固定密码）。
2. 上传页加**"上传人部门"、"上传人姓名"必填输入框**，不填无法上传。
3. 实现**上传记录表格**：统计文件名、上传人部门、上传人姓名、上传时间，便于管理员查询"谁在什么时间上传了什么合同"，起备份和查询作用。

**实现**
- 窗口二维码上方显示橙色大字密码。
- 上传页两个必填输入框，**前后端双重校验**（前端 alert + 服务端 400 拒绝）。
- 每次上传自动追加记录到 `上传记录.xlsx`：上传时间/部门/姓名/文件名/保存路径；多线程加锁。
- 窗口新增【打开上传记录】按钮一键打开。

### R9 热点名称显示
**需求描述**：在 WiFi 热点密码上方加一行：**WiFi 热点名称：打印机主机连接**。

**实现**
- 窗口密码上方新增热点名称行（名称/密码均为用户指定固定值，需在 Windows 移动热点设置里保持一致）。

### R10 样式统一 + 记录列宽优化
**需求描述**
1. WiFi 热点名称那行字的字体、字号、颜色与下一行密码保持一致。
2. 上传记录第一列"上传时间"宽度拉宽——时间字符串长，CSV 打开时默认显示一堆 `#######`。

**实现**
- 名称行样式改为与密码一致（微软雅黑 14 加粗、橙色）。
- **记录文件从 CSV 升级为 xlsx**（CSV 无法设置列宽，xlsx 可预设）：上传时间列宽 22、部门 14、姓名 12、文件名 34、保存路径 55，打开即合适宽度，不再出现 `#######`。依赖 openpyxl 打包进 exe。

### R11 部门输入框提示优化
**需求描述**：上传人部门输入框的提示语里"如：采购部"删掉（公司没有采购部）。

**实现**
- placeholder 改为"上传人部门（必填）"。

- 标题与副标题说明

- **WiFi 热点密码：73556088**（橙色加粗）
- 大二维码（程序动态生成，扫码直接进上传页）
- 上传地址（点击复制）
- 保存目录 + 【修改…】按钮（文件夹对话框，自动记忆）
- 已接收文件列表（点击文件名打开文件）
- 【打开上传记录】按钮（打开 .xlsx 记录表）
- 无黑窗口（windowed 打包）；端口占用等错误弹窗提示

### 3.2 手机上传页
- 上传人部门（必填）、上传人姓名（必填）——不填无法上传
- 文件选择（支持批量多选、进度显示）
- 微信文件导出引导（Android / iPhone 分列 + 图片）
- 保存目录实时显示

- `上传记录.xlsx`：每次上传自动追加（时间/部门/姓名/文件名/路径），预设列宽
- `received/`：收到的文件本体（同名自动加 (1)）
- `config.json`：保存目录记忆

### 3.4 传输特性
- 全程局域网直连，不经互联网（符合隔离环境要求）
- 单文件上限 500MB
- 同名不覆盖；中文文件名/路径正常
- 上传后自动打开保存文件夹（5 秒节流）

## 四、技术实现要点（供后续维护参考）

### 4.1 技术栈
- Python（打包环境：系统 Python 3.14，含 tkinter）
- 运行时依赖：tkinter（窗口）、qrcode + pillow（二维码）、openpyxl（xlsx 记录）、全部为打包内置，主机无需安装
- PyInstaller 打包：`--onefile --windowed`，输出单文件 exe（约 19MB）

### 4.2 关键设计决策
| 决策 | 原因 |
|---|---|
| 二维码只传地址凭证，不传文件 | 二维码容量仅 2~3KB，装不下文件 |
| 手机→主机走 WiFi 热点局域网直连 | 主机不能联网，但允许设备间直连 |
| 上传页引导微信文件先"保存/导出"再传 | 微信私有目录网页无法访问（系统限制），无技术绕过 |
| windowed 打包 + stdout/stderr 重定向 | 隐藏黑窗口，同事不会误以为故障 |
| 记录用 xlsx 而非 CSV | CSV 无法设置列宽，Excel 打开时间列显示 ####### |
| 必填部门/姓名做前后端双重校验 | 防止绕过前端直接 POST |

### 4.3 踩过的坑（重要）
1. **PyInstaller 路径问题**：`__file__` 指向 _MEIPASS 临时目录 → 必须 `sys.frozen` 判断用 exe 目录，否则 config/文件写丢。
2. **windowed 无标准流**：stdout/stderr 为 None，print 直接崩 → 启动时重定向（devnull / error.log）。
3. **改调用点漏改函数签名**：windowed 下异常只弹"Unhandled exception"看不到 traceback → 出问题先跑源码复现。
4. **exe 文件被占用**：旧 exe 进程未退出时，新 exe 无法覆盖 → 打包前先杀进程、mv 后验证时间戳/体积。
5. **CSV 列宽**：CSV 是纯文本，无法设列宽 → 换 xlsx。

## 五、使用流程（简述）

1. 主机打开 Windows 移动热点（名称：打印机主机连接；密码：73556088）。
2. 双击 receive_server.exe，屏幕弹出二维码窗口。
3. 同事手机连热点 → 扫屏幕二维码 → 填部门/姓名（必填）→ 选文件上传 → 电脑自动弹文件夹。
4. 管理员点【打开上传记录】查看 `上传记录.xlsx` 查询。

## 六、已知限制

- **微信文件必须先"保存/导出"**（微信私有目录限制，无技术绕过）。
- 单文件上限 500MB。
- 单机版、无账号体系；安全性依赖热点密码（建议定期更换）。
- 记录表与文件仅存在主机本地，主机不能联网，**需定期人工备份**。
- 仅支持同一时间一个主机开启服务；端口固定 8080。

## 七、可能的后续优化方向（备选，未实施）

- 收到文件后自动送入打印队列（需对接打印机驱动）。
- 上传记录按日期自动分表 / 增加统计视图（各部门上传次数）。
- 记录表定期提醒备份 / 导出功能。
- 开机自动启动热点 + 程序的一键脚本。
- 局域网内其他电脑（非手机）直接访问上传页。
