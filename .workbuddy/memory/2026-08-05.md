## 扫码直连文件传输工具（printer-share）
- 场景：隔离环境 Windows 主机（不能联网）连接特殊打印机，需要手机扫码传文件到主机。
- 方案：二维码当凭证（内容为 http://192.168.137.1:8080），手机连主机 WiFi 移动热点后走局域网直连上传，全程不经互联网。
- 交付物（`printer-share/` 目录）：
  - `receive_server.py`：Python 纯标准库 HTTP 上传服务 + 内嵌网页上传页 + config.json 记住保存目录 + 同名文件自动加 (1) 后缀 + 单文件上限 500MB。
  - `使用说明.txt`：三步使用法（开热点 → 运行脚本 → 手机扫码上传）、开机自启、改目录方法。
  - `上传二维码.png`：打印版二维码（含标题文字），本机用 qrcode 库生成（_gen_qrcode.py 可重新生成）。
- 已本地测试通过：上传落盘、/dir 接口、同名不覆盖、自定义目录参数、config.json 记忆目录、无参重启沿用上次目录。
- 关键约束：主机不能联网 → 脚本必须零第三方依赖（标准库）；二维码装不下文件，只传连接信息。

## 新版 exe 覆盖失败事故与重打包（追加）
- 教训：第二次打包后 `mv dist/receive_server.exe ./receive_server.exe` 时，旧版 exe 进程仍在运行 → Windows 文件被占用 → mv 静默失败，新 exe 留在 dist 又被误删，交付目录里一直是旧版（用户发现）。
- 处理：确认无 receive_server 进程后删除旧 exe → 用 pack venv 重新打包 → mv 成功。
- 新版 exe 体积 19,204,599 字节（18.3MB，含 tkinter/qrcode/pillow），旧版仅 8,074,707 字节（7.7MB）——体积可区分新旧。
- **流程规范**：打包前先确认无进程占用（Stop-Process / tasklist），mv 后必须 ls 验证时间戳与体积。

## 微信文件导出引导版（追加）
- 痛点：同事文件多来自微信，微信文件存私有目录，网页上传选择器看不到 → 系统"没用"。
- 分析：手机系统安全限制，网页无法直接读微信私有目录，唯一路径是"先导出到公共存储再上传"。无法技术绕过，只能做引导。

- 已重打包 windowed exe（19M，20:31），实测：引导区内容返回正常、多文件上传正常。使用说明已补充微信导出步骤。
